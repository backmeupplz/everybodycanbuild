Everybody can build

You don't need to be a programmer to make apps, websites, scripts and little helpers anymore. You need an idea and Claude. This page gets you from zero to building in one afternoon, and our Telegram group is there whenever you get stuck.

Start with step 1 Join the Telegram group

What you need

  • A Mac or a Windows PC. A Mac gets the most out of this, because Claude can only take over the whole screen on a Mac.
  • A paid Claude plan, Pro or Max, from claude.com/pricing. Pro is enough to start, and Max is worth it once you build every day.
  • Google Chrome, for the step where Claude learns to use your browser.
1
The only step you do by hand

Install Claude Code

Claude Code is Claude living in a terminal on your computer, where it can create files, run programs and set things up for you. Open a terminal: on a Mac press ⌘ Space and type Terminal, and on Windows press Start and type PowerShell (not Command Prompt). Then paste this line and press Enter.

curl -fsSL https://claude.ai/install.sh | bash
irm https://claude.ai/install.ps1 | iex

When it finishes, close the terminal window and open a fresh one so it notices the new program. Make a folder for your projects and start Claude inside it:

mkdir builds
cd builds
claude

Claude opens your browser so you can log in with your Claude account, and when it asks whether you trust the folder, say yes. Back in the terminal, type /model, pick Opus 5.5 with the arrow keys and press Enter, because it is the smartest model and the rest of this guide counts on it. If your Mac ever pops up a window offering to install developer tools, click Install and let it finish.

How to talk to Claude: type or paste what you want and press Enter. Claude asks before doing anything risky, and you can stop it at any moment with Esc. Next time you want to build, open a terminal and type cd builds and then claude, or claude --continue to pick up your last conversation where you left it.

From here on you don't type any commands. Each step below is a prompt that you copy and paste into Claude, and Claude does the setup itself. Whenever it needs your hands for a login or a switch in Settings, it stops and tells you exactly what to click. Claude can't type your computer's password for you, so when something needs it, Claude gives you a line to paste into a second terminal window instead, which is normal.

Paste into Claude

Let Claude use your browser

With browser use, Claude can open websites in your Chrome, click around, fill in forms and check that the things it builds actually work. It uses the browser you're already logged into, so it can help with your real accounts.

Set yourself up to control my Chrome browser with the official Claude in Chrome extension. Read https://code.claude.com/docs/en/chrome first so you follow the current steps.

Walk me through the parts only I can do, one at a time, and wait for me after each: installing the extension from the Chrome Web Store, signing in to it with the same Claude account I use here, and anything I need to type or restart in this terminal. If you need to be restarted, give me the exact line to type and remind me that "claude --continue" brings this conversation back. Turn browser use on by default so I don't have to do this again.

When it works, prove it: open a new tab, go to wikipedia.org, and tell me today's featured article.
3
Paste into Claude · Mac only

Let Claude use your whole computer

Computer use lets Claude see your screen and use any app with the mouse and keyboard, like Numbers, Photos or System Settings. It is a Mac feature in Claude Code for now. On Windows, skip this step: browser use covers most of what you'll need.

Turn on your computer-use ability on this Mac. Read https://code.claude.com/docs/en/computer-use first so you follow the current steps.

If my plan or Claude Code version doesn't support it, tell me what to change and stop there. Otherwise tell me exactly what I have to do myself, one step at a time, and wait for me after each: the menu I need to open in this terminal, and the Accessibility and Screen Recording switches in macOS System Settings. macOS may make me quit and reopen the terminal, so before that, tell me how to get back to this conversation (cd builds, then claude --continue).

When it works, prove it: open Calculator, work out 1234 × 5678 by clicking its buttons, and read me the answer from the screen.
While Claude drives: it sees whatever is on your screen, so close your banking and password windows first. You approve each app it wants to use, and Esc takes control back right away.

What to ask for once it works

Describe the result you want, say what "done" looks like, and tell Claude what it must ask you about first. Claude is good at checking its own work, so ask it to.

BuildMake me a one-page website for my bakery with our hours and menu, open it in Chrome, and fix anything that looks off on a phone-sized window.
BrowseFind three flights to Lisbon for the second week of March under $500. Put them in a table, and don't book anything.
Tidy upLook through my Downloads folder, sort everything into folders by type, and show me the plan before you move a single file.
Use any appOpen Numbers and turn the receipts in ~/Desktop/receipts into a monthly budget spreadsheet with a chart.
4
Paste into Claude

Give Claude passwords safely

Sooner or later Claude will need a password or an API key, for example to publish your website or log in to a service. Pasting those into the chat is a bad habit, because the chat is saved and you lose track of where your secrets went. Instead, Claude gets its own small Bitwarden vault, separate from your personal passwords, and fetches secrets from it straight into the programs that need them.

Set up safe secret storage for yourself using the Bitwarden CLI. Follow these rules the whole time: never ask me to type a password into this chat, and never print a secret's value, in your messages or in command output.

1. Install the official Bitwarden CLI ("bw") for my operating system. If that needs my computer's password, give me the exact line to paste into a second terminal window.
2. Have me create a separate free Bitwarden account at bitwarden.com just for you (an email alias like name+claude@gmail.com works), so you can never see my personal vault. Remind me to pick a master password I don't use anywhere else and write it on paper, because Bitwarden can't recover it. Then have me add an item named "test" with a dummy password like hello123 in the Bitwarden web vault.
3. Write a small unlock script that I run myself in a separate terminal window, and make sure it runs on my operating system without extra fiddling. It logs in to that account, asking me for the email, master password and any emailed login code with hidden prompts, then saves only the session key to a file in my home folder that only my user can read.
4. Write a helper command that takes an item name, an environment variable name and a command, and runs that command with the item's password in that variable, without ever printing it or putting it on a command line. If the vault is locked, it should say so and tell me to run the unlock script.
5. Add short instructions to the CLAUDE.md file in my home folder's .claude directory so every future Claude session knows to use this helper for secrets, never prints them, and asks me to add any secret it needs to the Claude vault.
6. Test it with the "test" item and show me only the number of characters in the password.
Using it later: when Claude says it needs, say, a Cloudflare token, add it to the Claude vault in the Bitwarden app or website under the name Claude suggests, then tell Claude it's there. If the vault has locked itself, run the unlock script again. Only put secrets in this vault that you're happy for Claude to use, because keeping them out of the chat doesn't stop Claude from using them.

Paste into Claude

Build from your phone, anywhere

Tailscale puts your computer and your phone on a private network of your own, so you can connect to the computer from anywhere without opening it up to the internet. SSH is how you connect, and once you're in you just type claude like you would at home. This works from another laptop too.

Set me up so I can connect to this computer from my phone or another computer, from anywhere, and keep working with you there. Use Tailscale and SSH, and walk me through the parts only I can do, one at a time, waiting for me after each.

Whenever something needs my computer's password, give me the exact line to paste into a second terminal window, or tell me what to click.

1. Install Tailscale on this computer from tailscale.com/download (on a Mac use the Standalone app, not the App Store one) and have me log in when you're ready.
2. Turn on an SSH server for my user only. On a Mac that means I switch on Remote Login in System Settings, on Windows the built-in OpenSSH Server, and on Linux Tailscale SSH. Make it accept SSH keys only, never passwords, and if you can, only connections that come through Tailscale.
3. Install tmux so my session keeps running if my phone loses signal. On Windows, explain what happens when the connection drops and set up the simplest workaround.
4. Stop the computer from going to sleep while it's plugged in, so I can always reach it. If it's a laptop, tell me the lid has to stay open, and tell me whether disk encryption means someone has to log in at the computer after a restart.
5. Tell me which apps to install on my phone: the Tailscale app, logged in to the same account, and Termius for SSH. Help me make an SSH key in Termius and send you only its public key, then add that key to this computer. Give me the exact host name and username to type in.
6. Save a short cheat sheet to my home folder as remote-cheatsheet.txt with how to connect and the commands to type once I'm in (start or reattach to tmux, then go to my builds folder and run claude).

When everything is set up, wait while I connect from my phone and tell you it worked.
Only want to chat from your phone? There's a simpler way for that. Inside Claude, type /remote-control, then open the Claude app on your phone and tap Code to keep talking to that same session. The SSH setup is for when you want the full computer from anywhere.
